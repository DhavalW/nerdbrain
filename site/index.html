Your AI agent gets better every time you use it.

You can't write down every preference in advance. nerdbrain doesn't ask you to. It watches how you work, writes down what it learned, and asks you to approve it. Say yes once, and your agent follows that rule in every project from then on.

It is a GitHub repository, and that's the whole of it. Nothing to install, no service to depend on, no account to create.

The problem

You can't write down a preference you haven't noticed yet.

The standard fix for a forgetful agent is an instructions file. Which means sitting down and guessing, up front, every preference you hold and every mistake it might make. Nobody can do that. So the file is always incomplete — and the gaps are exactly where you keep making the same correction.

Writing more doesn't help either. Past a certain length the file gets read selectively, so the rules you did write stop being followed.

Without

  • The same correction, every week, in every project.
  • A skill or rule to hand-write for every small preference.
  • A 900-line CLAUDE.md the agent reads selectively.
  • Invented method names, from docs that changed last quarter.
  • Everything you taught it locked inside one session.

With nerdbrain

  • You correct it once. It writes the rule itself.
  • Nothing to anticipate — it learns from what actually happened.
  • Small packs, and only the ones this task needs get loaded.
  • Real docs, indexed by topic, read six pages at a time.
  • A repo you own, that keeps getting more like you.
What you get

It learns. You approve. It sticks.

Ordered by what changes your day the most.

01

You stop writing rules. It writes them.

A correction you make today, a preference you mention in passing, an approach that held up under pressure — the agent notices it, strips out what was specific to this project, and writes it down. You say yes once. From then on it applies everywhere, including in projects that don't exist yet.

02

It fits you more closely every month

Each approved rule closes a little more of the gap between what you'd have done and what the agent does. Month six is measurably better than month one, and you didn't do anything extra to get there.

03

Your agent learns from everyone else's, too

It's an open-source repo, so you fork it. When a rule turns out to be true for anyone rather than only for your project, the agent offers to send it back to the original as a pull request. What gets merged there flows down to every other fork. A hundred people's agents learning in parallel beats one learning alone. How that works →

04

Nothing changes without your yes

The agent can write down whatever it notices — that changes nothing on its own. A note only becomes a rule when you approve it, one item at a time. Silence is never taken as agreement.

05

Fewer questions, and all at the start

Everything the brain already knows arrives at the decision point pre-filled. What is left gets asked once, in one batch, before building starts — never as a pop-up four hours in.

06

Fewer mistakes from stale training data

The docs your work depends on live in the repo as indexed snapshots, mapped topic-to-page. The agent reads the actual reference instead of recalling an API that changed after its cutoff.

07

It's a repo you own

Your preferences, your context, your captured documents — in your repository, public or private as you choose. Nothing is uploaded anywhere to make this work, and nothing runs in the background.

Shared learning

One person's fix becomes everyone's.

This is the second reason it's open source, and the more interesting one. A private instructions file only ever learns from you. A fork of a public repo can learn from everybody who runs one.

What goes up

  • The rule itself, and nothing else. Never the work that produced it.
  • Stripped of any project, employer, client or internal service first. If stripping that leaves nothing, there was nothing general in it.
  • Only when you say so. Silence is a no, the same as everywhere else here.

What never leaves your fork

  • Your captured documents, and the queue of what to capture next. Those never move between forks in either direction, by any route.
  • The evidence behind a rule — the code, the conversation, the project it came from.
  • Anything sensitive. That bar doesn't move because the audience got wider.
How it works

Notice, write down, approve, apply.

It turns on one separation: writing something down and giving it authority are two different acts. Writing is free, so nothing gets lost. Authority needs your yes, one item at a time — so nothing governs your work without you.

01

Route

A router picks the handful of small packs this task needs. The other thirty stay out of the way.

02

Work

The agent follows those packs. Anything you say overrides all of them.

03

Notice

What the task taught gets written down, with what makes it think so. No permission needed — a note governs nothing.

04 · YOUR CALL

Approve

Merge a pull request, or name the item in chat. Silence is never a yes.

05

Apply

It's a rule now — loaded on exactly the tasks it fits, from here on.

The partWhat it doesWhat it prevents
The router Matches the task to a few small packs, and re-checks when the work changes shape. One long instructions file that gets partly ignored.
The ledger Writes down what a session noticed, with the evidence — seen once, seen three times, or said outright. A lesson dying with the session that had it.
The approval gate Nothing becomes a rule without your yes, per item, through a channel that works while you're away. An agent quietly changing how it works on you.
The doc index Maps every topic in your PDFs to a page range, so the agent reads six pages instead of guessing. Invented APIs and quoted limits that went stale.
The consistency check Runs on every push: references resolve, packs are routed, notes parse, always-loaded files stay small. A brain that rots silently as it grows.

An entry here governs nothing. It is a note, not a rule. That is exactly why writing one needs no permission — and why turning it into a rule still needs your yes.

Your documentation

Bring the docs your work actually depends on.

Vendor APIs, platform guides, contracts, regulations, internal specs. Drop a PDF into docs/references/ and push — a workflow drafts its page map and opens a pull request. From then on the agent reads the reference instead of recalling one.

Any PDF with selectable text

  • An export, a spec, a scan that has been through OCR.
  • Indexed topic-to-page, so a lookup costs six pages, not six hundred.
  • Packs refer to topics by name, so a refreshed document that renumbers every page breaks nothing.
  • Prices and limits are stored as a link and a check-by date, never as a copied number that quietly goes stale.

The shelf fills itself

  • Docs that only exist as a website? SiteToPDF is the companion tool: it turns a documentation site into the dated PDFs this index is shaped around.
  • When a session needs docs you don't have, it writes a row saying what and where. SiteToPDF reads that list and offers you each one for a single click.
  • The next session checks the file landed, indexes it, and clears the row. Nothing is ever crawled that you didn't approve.
Get started

Fork it, attach it, and carry on working.

Works with Claude Code today. It's markdown in a git repo, so in principle any agent that can read a repository can use it — but Claude Code is the only one it has been tested with so far.

01

Fork it

The brain fills up with your preferences, so start by making it your repository.

02

Attach it to a project

Add your fork to the session, next to the project you're working on. A second repository on the web; an added directory in the terminal.

03

Work as normal

It turns itself on — no command to type. The agent loads what fits the task and follows it.

04 · YOUR CALL

Approve what it learned

It asks to turn what it noticed into a rule. Approve the good ones; ignoring the rest costs nothing.

05

Send the common ones upstream

Every so often, the rules that would help anyone go back to the original — with your permission — and reach every other fork.

# steps 1 and 2, in the terminal
$ git clone https://github.com/<you>/nerdbrain.git ~/.nerdbrain
$ claude --add-dir ~/.nerdbrain

# optional: install the skills, and type /nerdbrain on demand
$ ~/.nerdbrain/install.sh
