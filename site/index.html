Your AI agent forgets everything. This one remembers.

nerdbrain is a pluggable brain you attach to any AI coding session. It learns how you work, keeps the documentation your work depends on close at hand, and travels with you between tools — because it's just a git repo you own.

The problem

You've explained yourself to an AI a hundred times.

Every session starts from zero. You correct the same things, restate the same preferences, and watch it confidently use an API that changed after its training cutoff. The usual fix — one enormous instructions file — fails quietly: past a certain length it gets partly ignored, so you stop adding to it, so it stops describing how you actually work.

Without

  • The same correction, every week, in every project.
  • A 900-line CLAUDE.md the agent reads selectively.
  • Invented method names, from docs that changed last quarter.
  • Four interruptions mid-build, none of them at a good moment.
  • Everything you taught it locked inside one vendor's tool.

With nerdbrain

  • A correction becomes a rule, and the rule outlives the session.
  • Only the small packs the task actually needs load — every one of them, and nothing else.
  • Real docs, indexed by topic, read six pages at a time.
  • Every question asked once, up front, before the work starts.
  • A git repo you own, that any agent can read.
What you get

It gets better every time you use it.

Ordered by what changes your day the most.

01

You stop writing instructions. It learns them.

A correction you make today, a preference said in passing, an approach that held under pressure — a session notices it, generalizes it past the project, and writes it down. You say yes once, and it applies in every project after that. The instructions file writes itself out of your ordinary work.

02

No lock-in, ever

It's markdown in a git repo. Any agent that can read a repository can use it. Switch harnesses, switch models, switch jobs — the brain comes with you.

03

Fewer errors from stale training data

The docs your work depends on live in the repo as indexed snapshots, mapped topic-to-page. The agent reads the actual reference instead of recalling an API that changed after its cutoff.

04

Fewer questions, asked at better times

Everything the brain already knows arrives at the decision point pre-filled. What is left gets asked once, in one batch, before building starts — never as a pop-up four hours in.

05

Private, because it's yours

Your preferences, your context, your captured documentation — in your own repository, public or private as you choose. Nothing is uploaded anywhere to make this work, and none of it travels when your fork syncs with the original: the captures and the worklists beside them stay in the clone that owns them.

06

Runs longer without you

The rules that survive are the ones that prevent failures you already hit. Long autonomous runs go further before they need a human, and stop cleanly when they do.

07

Everyone's brain gets smarter than yours alone

A rule that would hold for anyone goes back upstream as a pull request — reviewed, generalized, stripped of the evidence that produced it. Your fork learns from your work; every fork learns from everyone's. That is the part a private instructions file can never do.

How it works

Notice, record, approve, apply.

The design turns on one separation: recording a lesson and giving it authority are two different acts. Recording is free, so nothing is ever lost. Authority needs your explicit yes, per item — so nothing governs your work without you.

01

Route

A router maps the task to the two-to-four packs it needs. The other thirty stay out of context.

02

Work

The agent follows those packs, with your word always beating any of them.

03

Notice

What the task taught goes to the ledger, with what it rests on. No permission needed — an entry governs nothing.

04 · YOUR CALL

Approve

Merge a pull request, or name an item's id in chat. Silence is never a yes.

05

Apply

It's a rule now — loaded on exactly the tasks it fits, forever.

MechanismWhat it doesThe failure it prevents
The router Maps task shape to a handful of small packs, and re-routes when the work turns. One long instructions file that gets partly ignored.
The ledger Records observations with their evidence — seen once, seen three times, or stated outright. A lesson dying with the session that noticed it.
The approval gate Nothing becomes a rule without an explicit yes, per item, through a channel that works while you're away. An agent quietly rewriting how it works on you.
The doc index Maps every topic in your PDFs to a page range, so the agent reads six pages instead of guessing. Invented APIs and quoted limits that went stale.
The consistency gate CI check: references resolve, packs are routed, ledger entries parse, always-loaded files stay small. A brain that rots silently as it grows.

An entry in the ledger governs nothing. That is exactly why writing one needs no permission — and why promoting one into a rule still needs your yes.

Your documentation

Bring the docs your work actually depends on.

Vendor APIs, platform guides, contracts, regulations, internal specs. Drop a PDF into docs/references/ and push — a workflow drafts its page map and opens a pull request. From then on the agent reads the reference instead of recalling one.

Any PDF with selectable text

  • An export, a spec, a scan that has been through OCR.
  • Indexed topic-to-page, so a lookup costs six pages, not six hundred.
  • Packs cite topics by name, so a refresh that renumbers every page breaks nothing.
  • Prices and limits are stored as pointers with a verify-by date, never as copied numbers.

Docs that only exist as a website

  • SiteToPDF is the companion tool: it turns a documentation site into the dated, multi-part PDFs this index is shaped around.
  • Nothing here requires it — the filename convention is the only contract.
  • A gap a session hits gets written down the moment it's noticed, because that session is the only one that knows.

And the library fills itself

  • Needed docs that aren't here yet? The agent writes a row into docs/scrape-list.md — where the capture belongs, where to start, and what the work needed it for.
  • SiteToPDF reads that queue and offers you each row. One click captures it, commits the PDF, and leaves a receipt.
  • The next session checks the PDF landed and is indexed, then clears the row. Nothing re-crawls while it waits, so a bad capture never repeats on a schedule.
  • Nothing is crawled that you didn't approve — the queue is a file, and a file can be written by anything with push access.

What that closes

  • The first loop keeps what you already captured current. This one is how the shelf grows.
  • The gap is noticed, queued, captured and filed without anyone remembering it existed.
  • Gaps no crawler can close — a spec behind a login, a page range a map missed — go to docs/wanted.md for a person instead.
Get started

Four minutes, then forget about it.

That last part is the goal. The repo does its work whether or not you think about it.

01

Fork it

The brain fills up with your preferences, so it should be your repository.

02

Clone & install

03

Attach it

Add the repo to a session beside the one you're working in — or type /nerdbrain.

04

Just work

It notices, records, and asks. Say yes to what's right, ignore the rest.

05

Send it home

Rules that would help anyone go back upstream as a pull request.
